# ADR-0004: React와 Vite를 프론트엔드 기준으로 사용한다

- 상태: 채택
- 일자: 2026-08-30

## 상황

서비스는 독립 웹 화면뿐 아니라 제휴사 홈페이지에 사용자 정보, 카드 추천, AI 상담 기능을 각각 삽입할 수 있어야 합니다. UI 상태가 늘어나더라도 기능 경계를 유지하고, TypeScript로 API 계약을 명확히 표현하며, 빠르게 테스트할 수 있는 기반이 필요합니다.

## 결정

- React 19와 TypeScript를 사용한다.
- 개발 서버와 배포 빌드는 Vite를 사용한다.
- 기능 코드는 `features/<기능>/api`, `features/<기능>/components`로 나눈다.
- API 응답은 정적 타입에만 의존하지 않고 런타임에서 검증한다.
- Vitest와 Testing Library로 사용자에게 보이는 상태 변화를 테스트한다.
- 로컬 개발의 `/api` 요청은 Vite 프록시로 Spring Boot에 전달한다.

## 이유

React 컴포넌트는 세 가지 삽입형 모듈의 독립적인 상태와 재사용 경계를 표현하기에 적합합니다. TypeScript는 변경 시점의 실수를 줄이며, 런타임 검증은 외부 응답이 선언과 다를 때 잘못된 데이터를 화면으로 전달하는 일을 막습니다. Vite는 간단한 설정으로 빠른 개발 서버와 최적화된 정적 빌드를 제공합니다.

## 결과

### 장점

- 화면과 기능을 컴포넌트 단위로 확장할 수 있다.
- API 계약 변경을 타입 검사와 테스트로 조기에 발견할 수 있다.
- 프론트엔드와 백엔드를 독립적으로 개발·배포할 수 있다.
- 로딩, 성공, 오류, 재시도 같은 사용자 상태를 테스트할 수 있다.

### 비용

- 정적 타입과 별도로 응답 검증 코드를 관리해야 한다.
- 삽입형 SDK를 제공할 때 스타일 격리와 호스트 통신 규약이 추가로 필요하다.
- 배포 환경에서는 백엔드 주소와 CORS 정책을 별도로 구성해야 한다.

## 재검토 조건

- 실제 제휴사 연동에서 Web Component나 iframe 격리가 필수로 확인될 때
- 모듈별 독립 배포가 필요해 번들 전략을 분리할 때
- 서버 렌더링이 검색 노출이나 초기 성능의 핵심 요구사항이 될 때

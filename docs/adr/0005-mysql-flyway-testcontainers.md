# ADR-0005: MySQL 스키마를 Flyway로 관리하고 실제 DB로 통합 테스트한다

- 상태: 승인
- 날짜: 2026-09-02

## 배경

사용자, 거래, 카드 상품처럼 관계와 정합성이 중요한 데이터를 MySQL에 저장할 예정이다. 개발자마다 설치 상태가 다른 로컬 DB에 의존하면 실행 결과를 재현하기 어렵고, 메모리 DB 테스트는 MySQL의 SQL 문법과 동작 차이를 놓칠 수 있다. 스키마도 수동으로 변경하면 환경마다 버전이 달라진다.

## 결정

- 개발용 DB는 Docker Compose로 `mysql:8.4.11`을 실행한다.
- 개발 데이터는 이름 있는 Docker 볼륨에 보존한다.
- DB 접속 정보는 환경 변수로 주입하고 실제 `.env`는 Git에서 제외한다.
- 스키마 변경은 Flyway의 버전 SQL로 관리한다.
- 백엔드 통합 테스트는 Testcontainers가 동일한 MySQL 이미지를 임시 실행해 검증한다.
- Actuator readiness에 DB 상태를 포함한다.

## 이유

- 이미지 버전을 고정하면 개발자와 CI의 DB 버전을 맞출 수 있다.
- 개발 DB와 테스트 DB의 생명주기를 분리하면 반복 개발과 테스트 격리를 함께 얻는다.
- Flyway 이력으로 코드가 기대하는 스키마 버전을 재현할 수 있다.
- 실제 MySQL 테스트는 전용 문법, 문자셋, 드라이버와 마이그레이션 문제를 조기에 발견한다.
- readiness는 DB 장애 시 로드 밸런서가 준비되지 않은 인스턴스를 구분할 근거가 된다.

## 결과

### 장점

- 신규 개발 환경을 문서화된 명령으로 다시 만들 수 있다.
- 스키마 변경 과정이 코드 리뷰와 Git 이력에 남는다.
- 테스트마다 격리된 실제 MySQL로 회귀를 검증한다.
- DB 중지와 복구가 readiness 상태에 반영된다.

### 비용

- 테스트 실행에 Docker Desktop이 필요하고 메모리 DB보다 시간이 더 든다.
- 이미지 다운로드와 컨테이너 시작 시간이 발생한다.
- 이미 적용된 마이그레이션을 수정하지 않는 운영 규칙이 필요하다.

## 검증 결과

- MySQL 8.4.11과 `utf8mb4`, `utf8mb4_0900_ai_ci` 설정을 확인했다.
- Flyway 버전 1 적용과 초기 데이터 조회를 확인했다.
- MySQL 중지 시 readiness HTTP 503, 재시작 후 HTTP 200을 확인했다.
- 전체 백엔드 자동화 테스트가 통과했다.

## 재검토 조건

- AWS RDS 버전 정책에 맞춰 MySQL 패치 버전을 갱신할 때
- 통합 테스트 시간이 개발 흐름을 방해해 테스트 계층 분리가 필요할 때
- 여러 서비스가 같은 스키마를 공유하게 되어 마이그레이션 소유권을 분리해야 할 때
